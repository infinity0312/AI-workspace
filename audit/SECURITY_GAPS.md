# 安全、权限与迁移风险

本阶段采用静态代码审查、已有回归和隔离诊断。下列缺口含需要后续验证的风险，按证据注明状态。

## 已见的控制

- **认证与隔离。** `http/app.ts` 设置请求 ID、禁用缓存、限制请求体并检查本机 Host 与写请求 Origin。`platform/security.ts::authenticate` 在 loopback 本机配置使用单一开发身份，服务模式验证 HS256、issuer、audience、时效和租户声明。 `domain/access.ts::workspace` 用 Workspace、租户及成员联表授权，写入拒绝 viewer。Job 详情与事件限定租户、成员和创建者或 owner。
- **外部数据。** `Jobs.modelAttempt` 调用前重查外部策略、Artifact 基线及证据。`readAiEvidence` 约束 Workspace、显式关系、来源生命周期、敏感级别、许可和最新快照。语料自动召回只覆盖当前项目和共享资料。关联项目允许的显式选源另走授权路径。
- **副作用。** `access.ts::idempotent` 以租户、用户、scope、key 和请求摘要去重已有键的写入。`Jobs.complete` 事务内检查租约并提交产物与状态。AI 分析和选段先产生 Patch，`Artifacts.resolve` 核对基线和证据收据后由用户采纳。
- **网络和协议。** `platform/public-web.ts::fetchPublic` 校验公共解析、固定连接地址、限制重定向与响应类型大小，拒绝 HTTPS 降级。专用检索客户端使用指定供应商地址。模型协议未开放任意工具、Shell 或数据库连接。上游内部推理在适配器解析时被排除。
- **最小日志。** `ContextSnapshotCreated` 保存模板和上下文摘要、证据 ID 等元数据。诊断注入的提示文本、凭证和内部推理标记未出现在可读运行事件。HTTP 错误日志记录 trace、类型和状态。原始任务输入、部分摘录和草稿仍可能在 Job 输入与检查点持久化。

## 缺口与迁移前验证

| 优先级 | 当前证据 | 验证与处理方向 |
| --- | --- | --- |
| 高 | 官方来源缺答和改写限定词丢失已在真实工作台复现。相同 DeepSeek 配置用于生成和语义核查，覆盖项由模型计划派生。 | 固定用户约束与独立人工判定。关键归因、范围、来源和数值失败应阻止采纳，验证记录需对应具体引用。 |
| 高 | 固定研究工作流在提交时只为 `used` 中的生成主张/摘要引用再次读取证据，随后还会写入 `result.quotes` 的摘录块。另有权限检查到网络调用之间的时间差。 | 增加撤回、策略变更和来源更新发生在阶段边界时的并发回归。明确本地摘录与外部调用的各自政策。静态发现尚未做泄漏复现。 |
| 高 | SQL 版本提交有租约检查，抓取、解析、对象存储及供应商用量各有独立 I/O 或事务。Worker 在阶段中断后可重复发起尚未检查点化的请求。 | 在目标 PostgreSQL、多 Worker 和真实对象存储验证 fence、幂等和中断恢复。工具注册要显式分级并记录执行状态。 |
| 中 | `job_events` 可按 cursor 读取，当前没有完整模型消息日志、版本化 Session Envelope、端到端 provider 请求 ID 或运行检查点保留/清理策略。 | 在设计 Session 回放前划分敏感级别、用户可见范围、保留期与删除路径。继续保护上游推理和凭证。 |
| 中 | 单次超时、字节估算、调用上限和一次固定等待重试存在。尚未发现租户/用户并发配额、全局费用阈值或 Retry-After 处理。单次领取期限在重领时重建。 | 建立累计期限、按用户或租户的并发与费用限额，对 429、超时、重领、供应商异常做灰度验证。 |
| 中 | 研究支持暂停/取消，文档分析和选段没有对应命令。解析和任务同进程路径可用，本阶段未验证面向不可信大文件的进程级隔离。 | 将取消扩展到所有模型工作流，统一 AbortSignal，验证解析隔离和资源上限。 |
| 中 | 本机项目暂无 Git 提交，生产 PostgreSQL/S3、权限迁移与备份恢复未演练。 | 建立可恢复的源码基线。需要切流前，在目标环境验证租户隔离、回滚及只读 Shadow。 |

本阶段用安全的合成输入验证现有门控和修订行为，结果见 [基线](CURRENT_BASELINE.md)。
