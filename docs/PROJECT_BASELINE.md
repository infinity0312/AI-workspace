# 项目实施基线

## 交接资料

后端以 `reference/交接文档/AI_Knowledge_Workspace_Backend_Spec/00…13` 为基线。前端以 `reference/交接文档/AI Knowledge Workspace UI 设计.md` 为交互和视觉参考。其余七份资料收录于 `reference/详细设计`。源目录包含 22 份 Markdown。工程采用 TypeScript、NestJS 和 npm workspaces，优先在 Windows 本地验证。原型界面可以沿用共享客户端和 API 契约重做。

## 交付路径

1. 把文本、链接或文件存到个人收件箱，整理成项目中的来源或知识笔记。工作空间搜索覆盖正文、来源段落、节点、结论和个人待整理资料。
2. 从已有来源发起研究，或从空白和现有文档发起联网分析。分析默认检索百科、论文和开放许可图片。正文经独立证据校验后生成提案，确认写入后保留原文引用、DOI 和图片署名。扫描 PDF 使用本地 OCR，保留页码并提示复核识别结果。
3. 在来源页查看引用影响，从原文段落提议结论。网页监测和手动检查保留快照。来源撤回、归档和变化会触发受影响结论的复核，历史证据仍可定位。
4. 管理文档名称、版本与回收站。Web IndexedDB、Windows SQLite 和 Android 调试版 SQLite 接入同一套草稿与 Mutation Outbox。Web 正式构建首次在线访问后可离线重开已缓存文档。
5. 创建个人学习目标、阶段任务和复习卡片。回答后按自评安排间隔复习。监测计划由 Worker 定期派发，检查运行权限和工作空间策略，并跳过重复在途任务。
6. 工作空间所有者可给现有租户账号设置编辑或只读权限。文档批注固定到版本或块，作者和所有者可解决及重开。图谱支持按项目、节点类型、关系和审核状态筛选，并聚焦节点的相邻关系。
7. 工作空间 ZIP 预检和恢复包括文档版本、回收站、来源生命周期、结论复核、批注和导出操作者自己的学习记录及符合权利条件的收件箱内容。归档对受限原始资料省略原文或附件，恢复到独立工作空间。恢复时保留批注原作者标识，访问权按新空间重建。当前 ZIP 压缩包限 8 MiB。

## 关键实施决定

| 事项 | 采用口径 |
| --- | --- |
| 数据与部署 | Windows 本机使用 PGlite、文件对象存储和单进程 Worker。服务端配置支持 PostgreSQL、S3 和独立 Worker。 |
| Canonical Artifact | 当前正式版本为 `1.0`。文档使用稳定 Block ID、不可变 Revision、Patch 提案和明确的恢复版本。 |
| 项目关系与权限 | 项目继承工作空间成员权限。研究和引用额外检查所选项目与显式关系。 |
| 同步 | 有版本的 Mutation、幂等写入、增量 Cursor 和三方合并。同一内容冲突时保留待处理草稿。 |
| 学习与监测 | 间隔复习使用本地规则。学习、收件箱和监测计划按账号隔离。用户可单独为定期研究授权外部处理。 |
| 数据迁移 | 导入只创建新空间并关闭外部处理。角色、监测计划、待采纳 AI 提案与运行队列由原空间管理。 |
| 界面 | Web、Windows 和 Android 共用 React 界面和平台协议。显示偏好保存在当前设备。 |

## 交接阶段覆盖

| 阶段 | 已实现与验收范围 | 仍需实现或验证 |
| --- | --- | --- |
| Phase 0 | Monorepo、SQL 迁移、CI、类型检查、测试、OpenAPI | 独立 PostgreSQL 和 S3 生产环境验收 |
| Phase 1 | 空间、项目、成员角色、Artifact、来源、证据、结论、关系、回收站 | 自助登录与身份接入、独立项目 ACL、永久删除与保留策略 |
| Phase 2 | DeepSeek 即时回答、证据综合、选区、文档分析与阶段检查点。独立证据判断、数值校验、限次修复、模型预算。 | 通用 DAG、独立专业 Agent 与 Skill 插件化、模型评测、金额计量、私有模型。详见 `AGENT_RUNTIME_AUDIT.md`。 |
| Phase 3 | 文本、网页、PDF、Office、图片与扫描 PDF OCR、来源变化与追溯、全文、可选向量、已确认知识召回、关系一跳证据召回 | 复杂版面和表格 OCR、独立解析进程、检索和引用质量评测 |
| Phase 4 | 结构化编辑、AI 差异预览、版本恢复、五种导出、统一块渲染器、LaTeX 排版、思维导图、时间脉络和关系图谱 | 高保真编辑器、复杂排版、完整引用样式、图谱自由布局和更大数据量 |
| Phase 5 | Web 与 Windows 离线草稿、重启与同步验收。Android 36 模拟器通过 SQLite 离线保存、冷启动和回网同步验收。 | 文件分片续传、离线保留和清理策略、各原生端真实设备测试 |
| Phase 6 | 外部处理授权、敏感级别、基础审计、Token 记录、ZIP 预检与恢复 | 生产密钥托管、PITR 与对象存储备份演练、安全和负载验收 |
| Phase 7 | 收件箱、来源库、学习目标、间隔复习、维护、定期监测、搜索、偏好和图谱筛选 | 共享学习模板、进阶复习与自动化规则、进度及通知联动 |
| Phase 8 | 共享空间角色、版本批注及审核、增量同步与三方合并、OpenAPI | CRDT 实时共编、Marketplace、独立 SDK 和 MCP、企业身份与运营管理、本地模型 |

原生交付以 Windows x64 优先。Android 调试版从 Windows 通过 ADB 连接本机服务。API 36 模拟器已验证安装、启动、断线编辑、重开、回网同步和文档改名。Android 生产登录与签名发布，macOS、iOS、HarmonyOS 原生壳与真机验收仍待实施。跨端接口见 `FRONTEND_HANDOFF.md`。
