# Quality Engine

`apps/api/src/runtime` 与 `apps/api/src/quality-engine` 是同级模块。Runtime 负责研究和文档分析的阶段调度、选段改写、公开来源、模型传输及运行预算。Quality Engine 负责任务契约、提示词注册、响应检查、证据和覆盖门控、上下文清单及质量事件定义。Runtime 调用 Quality Engine 的校验规则。Job 服务管理租约、权限、数据库写入和版本提交。

## 已接入的机制

| 机制 | 当前实现 |
| --- | --- |
| 任务契约 | 入队时把工作空间、运行 ID、原始任务输入和目标文档版本绑定到契约。运行或恢复时校验摘要。任务目标改变需要发起新运行。旧任务缺少契约时在首次执行时补齐。 |
| 提示词注册 | 每个调用以固定提示词 ID 发起，记录版本、模板摘要、输出模式和结构版本。研究、分析、核查和补写各用自己的模板。 |
| 上下文审计 | 调用前重新校验文档版本、外部授权和已保存证据。运行事件记录提示词、模型配置、上下文摘要、证据快照和预算，公开检索临时候选 ID 与持久证据 ID 分开标识。完整请求正文、响应正文和模型内部推理不进入新审计事件。 |
| DeepSeek 适配 | 固定 Chat Completions、非思考模式、有限输出。区分空白、截断、非法 JSON、非正常停止、限流和网络错误。收到带用量的响应时记录实际用量，即使生成内容被拒绝。 |
| 覆盖账本 | 对检索计划的子问题生成运行内稳定 ID。核查结果须引用已保留且直接回答该问题的主张。提案事务把映射写到运行事件，关联具体内容块和已保存证据。未得到支持的子问题记录为 unanswered。 |
| 修复与恢复 | 检索规划和初稿遇到可修复的格式问题时各有一次定向修复机会，继续受统一预算约束。选定单个来源时也生成检索问题计划，以记录可回答项和资料缺口。格式失败标记进入检查点。证据不足时沿用定向补写，提交前仍核验文档和来源版本。 |

已有运行的轮询与事件接口继续可用。此次升级复用 `jobs.checkpoint`、`job_events` 和 `model_usage`，可直接使用现有本机数据库。工作流版本升级时重算旧任务的分析阶段或研究综合阶段，并保留已计入的预算。已生成提案仍由现有证据收据规则控制采纳。

## 从运行事件排查

在已有的分析、研究或改写运行事件接口中，按序查看：

1. `TaskContractCreated` 记录契约版本、请求摘要和目标版本。
2. `ContextSnapshotCreated` 按调用序号记录提示词、模型配置、输入上界和证据版本。
3. `ModelInvocationCompleted` 或 `ModelInvocationFailed` 记录完成原因、耗时、协议结果及可用的供应商用量。
4. `AnalysisStageCompleted` 记录阶段以及可修复的格式失败。终止的门控记录在 `QualityGateFailed`。
5. `RequirementLedgerRecorded` 给出提案 ID、基线版本、检索问题 ID 及简短标签、提案块和证据引用。账本描述该次提案，用户随后修改文档会形成独立版本。

覆盖账本的分母来自本次检索计划。原始用户目标随调用和契约保留。跨主题的要求抽取质量、强制验收项和术语锁定仍需通过人工标注用例校准。语义核查使用当前配置的模型，引用位置和确定性数值规则由应用执行。原样出现在引文中的技术标识可以进入中文解释，实测数值、单位和日期仍以证据原文为准。

## Windows 本机验收

用 `npm.cmd test` 验证边界和门控，再用 `npm.cmd run test:e2e` 验证界面与版本写入。实际内容验收应从工作台提交真实 DeepSeek 任务，逐项核对用户要求、引用来源、原文支持、精确值和修改前后版本。自动覆盖率适合定位缺项，事实与归因仍需独立核对。

如需在独立数据上启动新版 API，先运行 `npm.cmd run build -w '@akw/api'`，在 PowerShell 中设置 `AKW_PORT`、`AKW_PGLITE_PATH` 和 `AKW_OBJECTS_PATH`，再运行 `npm.cmd run start -w '@akw/api'`。Windows 客户端使用 `AKW_DESKTOP_API_PORT` 连接对应端口。

## 验收与后续范围

- `npm.cmd test` 验证任务目标篡改、空白输出修复、截断拦截、来源权限、阶段恢复，以及账本到提案和证据的映射。
- `npm.cmd run test:deepseek` 验证真实模型的问答、研究、选段改写和文档分析。
- `npm.cmd run test:e2e` 验证共享前端流程。
- 术语注册和人工确认的需求版本属于后续契约建设。正式评测平台需要先积累可复用的跨主题人工金标。当前调用采用非思考模式，工具调用由应用现有流程负责。启用模型工具或思考模式前需分别验证协议和授权边界。
